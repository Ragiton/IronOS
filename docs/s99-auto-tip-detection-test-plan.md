# S99 C245 startup auto-detection: implementation and validation plan

**Status:** planning only. No firmware change or hardware test has been performed by this plan. No powered test, including a dummy-load run, is ready to start until the exact source models, the S99 XT60-to-USB-C cable wiring/rating, and independent cutoff commissioning are settled. The current HIL runner remains simulation-only and refuses live mode.

**Target:** distinguish the known 2.5 Ω and 5.5 Ω C245 cartridge profiles at S99 startup, with the iron cold and the tip unloaded. The candidate is a bounded thermal-response classifier. It would infer a cartridge class from the tip-temperature response to a controlled probe; it would not measure resistance directly.

**Initial hardware scope requested:** one S99, one USB-C battery, one USB-C wall charger, one bench DC supply, three tips bundled with the S99, and three official JBC tips. This is an initial characterization fixture, not broad release qualification. Exact source models, S99 power-cable wiring/rating, and cutoff hardware are not yet confirmed. Give every tip a sample ID and measure its cold resistance; do not infer its resistance class from whether it is bundled or official JBC.

**Decision rule:** do not implement or enable software-only detection unless the team demonstrates a repeatable, discriminating probe that stays within independently verified electrical and thermal limits on every supported S99 revision and source type. If the stock hardware cannot meet that bar, document the required hardware changes or reject the software-only feature.

## 1. Repository and current behavior

GitHub issue searches performed on 2026-10-18 for `S99 auto detect`, `C245 resistance`, and `S99 tip resistance` did not find an existing issue for this feature. The generic `auto-detect tip` search returned closed issue [#1387, “Calibrate Temperature”](https://github.com/Ralim/IronOS/issues/1387), which is about temperature calibration rather than S99 cartridge identification. No matching issue or pull request for S99 startup resistance auto-detection was found.

Relevant upstream work is safety-related and must remain an explicit integration gate:

- [Issue #2244](https://github.com/Ralim/IronOS/issues/2244) records the S99/JBC cartridge problem.
- [PR #2248](https://github.com/Ralim/IronOS/pull/2248) is experimental S99 2.5 Ω output-stage work. Its reports include 20 V / 2.5 Ω operation producing 8 A pulses, a measured MOSFET gate turn-off tail of roughly 35–48 µs, charger trips under several pulse profiles, MOSFET heating, and problematic gate drive at low input voltage. The proposed 15 V / 6 A or PPS/no-chop paths are not a validated safety guarantee.
- [Draft PR #2250](https://github.com/Ralim/IronOS/pull/2250) is PID tuning work stacked on #2248. The changed controller can alter the thermal transient used by a classifier, so the feature must be qualified against both controller configurations.

This feature branch is a local snapshot at `a08a3fbc`. Upstream PR #2248 has since merged, and its code is newer than this checkout; compare and integrate it before firmware work. PR #2250 remains a draft. Neither upstream work nor a merge is a safety qualification. Battery and power-bank qualification is an identified gap in the reported S99 experiments.

Code references below are for this local feature-branch snapshot (`a08a3fbc`); compare them with current upstream `dev` and merged PR #2248 before firmware work:

- [`configuration.h`](../source/Core/BSP/Sequre/configuration.h#L280-L288) sets `TIP_RESISTANCE` to 55 (5.5 Ω), enables manual `TIPTYPE_C245` selection, and does not define `AUTO_TIP_SELECTION` or enable a S99 `Tip Sense` path. The S99 menu therefore supports selecting 5.5 Ω or 2.5 Ω manually; hardware auto-sense is unsupported.
- [`settings.yaml`](../source/Settings/settings.yaml#L272-L276) defaults `SolderingTipType` to enum value 0. [`Settings.h`](../source/Core/Inc/Settings.h#L170-L173) identifies that first C245 option as 5.5 Ω, and [`Settings.cpp`](../source/Core/Src/Settings.cpp#L323-L329) maps it to resistance value 55. This is the current startup profile unless a saved manual selection overrides it.
- [`BSP.cpp`](../source/Core/BSP/Sequre/BSP.cpp#L466-L492) uses the selected resistance or the compile-time default. The shared `COPPER_HEATER_COIL` branch at lines 467–480 contains a 5.0 Ω cold-start value, but the S99 configuration does not enable that macro; it is not the S99 startup behavior.
- [`getTipChopDutyX256()`](../source/Core/BSP/Sequre/BSP.cpp#L170-L221) estimates tip current from measured input voltage and configured resistance, compares it with negotiated PD source-current data or the user power limit, and caps PWM duty. This is a software estimate and an average-duty cap. It is not live current sensing, and it does not clamp the peak current inside each MOSFET pulse. Do not treat it as overcurrent protection for a detection pulse.
- In this checkout, [`BSP.cpp`](../source/Core/BSP/Sequre/BSP.cpp#L110-L221) and [`Setup.cpp`](../source/Core/BSP/Sequre/Setup.cpp#L376-L400) define five TIM4 chopping presets: about 11.2, 5.9, 3.0, 2.4, and 1.5 kHz. The code starts one step slower at about 5.9 kHz when its estimated tip current exceeds 5.5 A, and thermal derating can step it down further. Source comments estimate about 0.4 W of switching loss at 11 kHz with a 5.5 Ω cartridge and about 0.9 W for a 2.5 Ω cartridge at that rate; these are unvalidated estimates, not measured temperature or loss results. At 20 V into 2.5 Ω, the ideal on-pulse current is 8 A. The timer arithmetic alone permits about 123 kHz with a zero prescaler, but this is not a firmware preset or a safe operating limit. **No maximum safe switching frequency has been established.** Do not raise the rate beyond the existing firmware choices or infer safety from average duty.

## 2. Safety questions to resolve before implementation

The thermal-response method is only a hypothesis until testing proves it. Response may vary with cartridge sample, cold resistance, ambient and initial tip temperature, sensor coupling, thermocouple noise, sampling phase, startup voltage, supply behavior, and firmware control-loop settings. Contact with a cold workpiece would change the response; all classifier trials must therefore use a mechanically verified no-contact fixture.

Before writing firmware, research the exact S99 revisions, schematics, BOM, gate-drive topology, thermocouple sampling sequence, MOSFET safe operating area, tip current waveform, and whether the live board has any hardware protection not represented in firmware. Current hardware review reports no onboard current-sense circuit or power-feedback loop, and the firmware exposes no live current-sense signal. Confirm those facts against each revision’s schematic and measurements; assume no active current feedback until proven otherwise. Confirm the debug interface and power-path isolation.

The low-resistance case is the limiting case. A low PWM duty reduces average energy but does not reduce the instantaneous current during the on portion of a pulse. At 20 V into 2.5 Ω, the idealized on-pulse current is 8 A. The gate delay and turn-off tail can make actual conduction longer than the command. A lower supply voltage is not automatically safer: #2248 reports weak gate drive and MOSFET heating in low-voltage/high-frequency cases. Do not run a real-tip ramp or a low-voltage live test until gate-source voltage and current waveforms establish a safe envelope.

An S99 power supply can trip before the MCU observes a thermal change. The probe schedule must never depend on the charger tolerating an unknown peak-current pulse. Define hard current, energy-per-pulse, total-energy, duration, input-voltage, MOSFET temperature, handle temperature, and tip-temperature limits from component ratings and instrumented measurements before the first powered probe.

## 3. Proposed firmware design after the safety gates

Keep the existing manual 5.5 Ω and 2.5 Ω choices. A manual choice bypasses detection and retains the existing behavior. Add an explicit Auto choice only after the research, model, and rig gates pass; keep it opt-in until qualification is complete. Preserve Auto as the user’s setting and hold the detected class in runtime state for that boot, rather than silently rewriting the saved manual selection.

Preserve settings compatibility. The current first C245 enum value and fresh-settings default are 5.5 Ω. Do not insert Auto ahead of existing enum values and reinterpret saved value 0. Append a new value or provide an explicit, tested migration; existing devices and fresh defaults must continue to select manual 5.5 Ω unless the user opts in.

The candidate detector should collect a heater-off baseline, execute only a pre-approved fixed probe schedule, and evaluate temperature change/slope over calibrated time windows. Freeze all pulse timing and decision thresholds from measured reference samples before held-out qualification. Account for input voltage, negotiated source state, sampling windows, and tip-temperature validity; do not infer available energy from PWM duty alone. A source-contract change or source instability invalidates the measurement and leaves heat disabled until a new safe start is explicitly requested.

The classifier returns only 2.5 Ω, 5.5 Ω, or unknown/ambiguous. Unknown, invalid, or low-confidence results leave the heater off and request manual selection. A recognized class may choose its matching profile only after the source is stable and the resulting power envelope has separately passed the applicable source and output-stage qualification. Detection must never increase the allowed power by itself. If these steps cannot be made safe on existing S99 hardware, do not add Auto mode; propose board changes or reject the feature.

## 4. Hardware and fixture plan

The planned rig has two independent layers: an agent-controlled experiment host and a fail-open safety controller that can remove input power without cooperation from the DUT, host, or firmware. A physically present human supervises every live test and has access to an E-stop. Once implemented, a test batch must run without prompts or in-run human input. At a tip change, the hardware runner must shut down, disconnect the source, verify bus discharge and the tip's cooldown, then end the batch. The human changes the tip only after that safe end state; a separate run starts for the next tip. The runner must not pause waiting for a person to handle a hot or powered tip.

### Initial setup, in plain steps

1. Identify and record the S99 board revision, firmware, device ID, and the exact model and output ratings of the USB-C battery, USB-C wall charger, and bench DC supply. Connect only one source at a time.
2. Identify the S99's actual power-input path. Confirm the connector, pinout, polarity, voltage/current rating, and construction of the included or explicitly S99-compatible XT60-to-Type-C DC lead before connecting a bench supply. Measure that lead's no-load output at the selected setting with the S99 disconnected. Do not guess a barrel connector, adapter, or pinout; do not energize the iron through an unverified lead.
3. Label the three bundled tips and three official JBC tips separately. Measure each one cold with a four-wire meter and record its resistance, condition, and identity. Do not assume the six samples cover both target resistance classes; if they do not, the missing class needs a separately identified sample before classifier work.
4. Fit an isolated, data-only debug connection and the measurement probes. Verify that debug or test equipment cannot power the S99 or back-feed its input.
5. Build and commission the fail-open cutoff, independent of the S99 and test computer, with an accessible E-stop and hard electrical, energy, time, and temperature limits. This cannot be configured until the input path, source ratings, and wiring are known; its independent response must be demonstrated with dummy loads.
6. Add a remotely controlled source selector that can disconnect the active source, verify bus discharge, switch exactly one source, and wait for a stable output/USB-C contract. Its connector and rating must match the confirmed source and S99 cable path. Never parallel or mix the supplies.
7. Calibrate the logger and instruments, confirm the guarded fixture and human-supervision interlock, then run offline and dummy-load checks before any real-tip probe.
8. For each tip batch, a human installs the tip while the S99 is off, disconnected, discharged, and below a pre-approved cooldown limit, then starts the manifest. The planned hardware runner will run the source cases and save results. The person remains present to supervise heat risk and can use the E-stop, but does not interact with the run. The batch must end in a powered-off, disconnected, discharged, cool state before another manual tip change. The numeric cooldown limit must be reviewed before live runs; this plan does not set it.

The current setup contains one S99, so it can characterize only that unit and revision. It cannot qualify other S99 revisions. A release-level claim still needs additional held-out S99 units and revisions, and adequate held-out tip samples.

The [S99 manufacturer's product page](https://sequremall.com/products/sequer-s99-soldering-iron-support-pd-qc-dc-pps-power-supply-compatible-with-c245-tip-for-drone-rc-model-welding-repair-tool-anti-static-welding-pen) describes Type-C input, PD/QC/PPS and DC operation, a 21 V maximum input, and maximum power of 150 W at 2.5 Ω or 75 W at the shipped ~5.5 Ω tip. The [SEQURE manual](https://drive.google.com/file/d/1beRgk3IVu5cX2lvbfYAYKvW80MfUj-Qq/view?usp=sharing), linked from the manufacturer's [manual index](https://sequremall.com/pages/instruction-manual), lists a 2.5 Ω tip at 20 V/7.2 A (144 W) and a 5.5 Ω tip at 11–12 V/2.0–2.1 A (23–25 W); those are published heating-test values, not measured MOSFET pulse limits or a safe probe schedule. Neither source documents a barrel jack or the included cable's exact pinout/polarity and current rating. Verify the exact cable and adapter before choosing source switches or cutoffs.

Measurement instruments have a preliminary procurement specification, but not a complete approved SKU list: target a four-channel oscilloscope with at least 100 MHz analog bandwidth and 1 GS/s, suitably rated differential probes for VBUS, VGS, and VDS, and a DC current probe with at least 10 A range (20 A is preferable) and bandwidth sufficient to resolve the switching edges and turn-off tail. Confirm the scope's sample rate per active channel, probe bandwidth, common-mode limits, voltage rating, and peak-current limit together. A low-inductance four-wire shunt with a differential probe is an alternative only after its insertion and fault limits are reviewed. Also use a four-wire meter and calibrated temperature sensors; a thermal camera is optional. The [Tektronix probe primer](https://www.tek.com/en/documents/whitepaper/abcs-probes-primer) explains differential probing and ground-lead effects; the [TCP0020/TCP2020 datasheet](https://www.tek.com/en/datasheet/current-probe/tcp0020-tcp2020-tcp202a) is an example of a DC probe class with 20 A RMS, 100 A peak-pulse, and 50 MHz specifications, not a required model. The [ChargerLAB ET240](https://www.power-z.com/products/chargerlab-power-z-et240) is a purchasable PD protocol analyzer, but its published product page does not establish a pass-through peak-current/pulse rating; do not route the high-current S99 path through it until that rating is confirmed.

#### Ripple and switching capture plan

The exact probe pads are not identified. The unit in hand appears to be S99-U1.3, while public teardown photographs may show U1.4; do not assume the layouts or nets match. A complete S99 schematic, PCB layout, or BOM has not been found in the public sources checked. The [IronOS S99 discussion](https://github.com/Ralim/IronOS/discussions/1919) and [S99 support work](https://github.com/Ralim/IronOS/pull/1920) provide firmware and photo context, not a verified net map. Before adding any wires, disconnect the supply, discharge the board, identify the exact revision and package orientation, and use continuity measurements to map input VBUS/return, the MOSFET source, drain and gate, and both heater-output conductors. Label the verified points. If the marking is confirmed as WSP4409A, the [Winsok datasheet](https://www.winsok.cn/upload/202405/WSP4409A.pdf) identifies a P-channel SOP-8L device rated −30 V, with pins 1–3 source, pin 4 gate, and pins 5–8 drain; this package map does not reveal the board's net connections or prove that the installed part is that device. Add only short, insulated, mechanically secured test leads to points confirmed by the continuity map.

Use a PD-preserving USB-C pass-through breakout/interposer to expose one VBUS conductor for the input-current probe. Do not cut the USB-C cable. The cable and interposer must support the negotiated contract and be documented as 5 A e-marked assemblies; USB-IF's [Type-C cable specification](https://www.usb.org/document-library/usb-type-cr-cable-and-connector-specification-release-25) requires electronic marking for the applicable 5 A cable types. A 20 V, 5 A contract is 100 W. A 5 A rating does not establish tolerance of an 8 A transient, so verify the breakout and cable pulse ratings before any powered capture; do not exceed their ratings. An ordinary inline watt meter reports averaged values and cannot substitute for a waveform current probe.

For the first captures, use a differential probe across VBUS and return at the S99 input, a differential probe directly across gate and source (VGS) on the continuity-mapped MOSFET, a DC current probe around one VBUS conductor, and a second DC current probe around one heater lead for output current. With one current probe, repeat the same baseline acquisition with the probe moved between the input and heater lead. For the switching-node pass, measure VBUS, VGS, and drain-to-source voltage (VDS) with differential probes, and use the remaining channel for either input or output current; repeat with the current probe on the other conductor if needed. This two-pass approach records the supply response and the MOSFET's switching behavior without assuming that a single-ended scope ground is safe on either switching node. Keep differential lead pairs short and close together. Never attach an earth-grounded probe clip to the gate, drain, heater output, or any other node until its reference is positively verified; never defeat the oscilloscope protective earth. Follow probe voltage, common-mode, and current ratings and the [Tektronix probing guidance](https://www.tek.com/en/documents/whitepaper/abcs-probes-primer).

#### Baseline and capacitor sequence

1. With power removed, complete the continuity map and install the insulated probe leads. Do not add a capacitor. Confirm the exact connector, adapter wiring, voltage, and polarity for every source. The bench supply's S99 adapter is not identified here; do not guess a barrel connector or pinout.
2. After the independent cutoff and dummy-load entry gates elsewhere in this plan pass, take a low-energy, current-limited bench baseline only if its connector and polarity are confirmed. Otherwise skip the bench source until identified. Keep a human present to monitor the DUT and nearby parts.
3. Save no-cap baseline captures for one USB-C wall charger, then the USB-C battery, then the bench supply only if it is correctly rated and connected. Use one source at a time. Record its model, contract/settings, cable and interposer, firmware hash, board revision, cold tip resistance or dummy-load value, scope/probe setup, selected firmware rate, and temperatures. Capture raw waveform files as well as screenshots and a CSV export where supported.
4. On approved noninductive dummy loads, record the unmodified firmware's existing discrete frequency choices from low to high, where the existing power, source, and thermal controls naturally select them. Monitor MOSFET-area temperature and source voltage/current. Do not bypass thermal derating, change firmware to force a rate, or test a rate that cannot be reached under the approved production configuration. Repeat the same settings for each source; source behavior is model-specific. Compare VBUS ripple/sag and peak and average input/output current separately. Only proceed to real tips after the dummy-load envelope and all safety gates pass.
5. Only after the no-cap baseline and measured peak/ripple values are reviewed should an input-capacitor trial be considered. Place a candidate only across the verified VBUS/return nodes near the measured switching-current loop, with power off. Choose its voltage, ripple-current, ESR/ESL, temperature, inrush, and transient ratings from measured maxima and the source/PD limits. Repeat the identical capture settings with the capacitor and compare against the stored baseline.

For planning the bench ladder only, the following are conservative exploratory setpoints suggested for review, not manufacturer limits or an authorization to power the device: begin with a measured 5.5 Ω tip at 11–12 V with a 3 A current limit, then 19–20 V with a 4 A limit. For a known 2.5 Ω dummy load, consider 12 V/5 A first, then evaluate the 20 V/8 A peak-pulse case only after the source, lead, load, cutoff, and pulse/energy limits have been verified. At 20 V into 2.5 Ω, 8 A is 160 W instantaneous, above the product listing's 150 W rating; it is a theoretical on-pulse measurement case, not an 8 A continuous operating target. The manual reports 20 V/7.2 A (144 W) for a 2.5 Ω tip. Never exceed the S99's published 21 V input maximum. Do not use a USB-C path for any condition whose measured current exceeds its 5 A cable/interposer rating; a 20 V/5 A PD contract is 100 W and does not establish tolerance of higher pulses. These levels must be replaced or withheld if measured component, source, adapter, cable, or cutoff limits are lower. Apply real-tip settings only after the corresponding dummy-load stage and all safety gates pass.

As a first-order illustration, if the capacitor alone supplied an 8 A pulse for the on-time `D/f`, its capacitive droop would be approximately `ΔV ≈ I·D/(f·C)`. For `D = 0.5` and an allowed `ΔV = 0.5 V`, this gives about 1.36 mF at 5.9 kHz and 714 µF at 11.2 kHz. For an ideal 20 V/2.5 Ω on-state (160 W) at `D = 0.625`, the average would be 100 W and the same droop target gives about 1.70 mF at 5.9 kHz or 893 µF at 11.2 kHz. These are not capacitor recommendations: the source contributes current during the pulse, and actual droop depends on source impedance and control response, wiring inductance, capacitor ESR/ESL, pulse shape, and recharge time. Higher switching frequency may lower the capacitance needed for a specified ripple under the same assumed pulse conditions, but it does not reduce the instantaneous 8 A tip current or the average energy required for a given heat output; it can increase MOSFET switching loss and change the source's peak-current waveform. Charger and battery protection responses must be measured for each model.

Do not add a capacitor directly across the MOSFET drain-source terminals or across the heater. Such a capacitor can create a larger switching-current transient and added switching loss. Sequre's recovered [25 V, 1 µF bulletin for S99 V1.3/V1.4](https://web.archive.org/web/20240519173242/https://sequremall.com/blogs/sequre-product-firmware-upgrade/s99-v1-07-firmware-upgrade) shows a small part near the USB-C/controller end, but does not label its net; it is not evidence of a heater-bus bulk capacitor or a confirmed ripple fix. If captures show ringing, first verify it is not probe-lead ringing, then characterize and size an RC snubber from the measured waveform using a method such as [TI's RC-snubber design note](https://www.ti.com/document-viewer/lit/html/SSZTBC7). Use [TI's MOSFET switching-loss guidance](https://www.ti.com/document-viewer/lit/html/SSZT810) to frame the frequency trade-off, not as a substitute for S99 measurement.

Potential selector/cutoff parts are **not an approved system**. The [Acroname S85 datasheet](https://acroname.com/sites/default/files/2025-07/S85-USB-C-SWITCH-v1.12.pdf) specifies 5 A maximum bidirectional VBUS current and 20 V recommended operating maximum. It may be a candidate only for a separately verified USB-C test condition within those limits; it does not cover the S99's full published input range and is below the idealized 8 A on-pulse at 20 V into 2.5 Ω. Do not use it for 2.5 Ω testing unless measured peak conditions and margins are independently shown to fit its rating. No USB-C selector/cutoff has been cleared for automated operation above 5 A. The [TI TPS259827LEVM](https://www.ti.com/tool/TPS259827LEVM) is a DC eFuse evaluation board (2.7–24 V, programmable 3–15 A), and [TE 2071583-4](https://www.te.com/en/product-2071583-4.html) is a DC contactor. These are procurement leads for a possible DC path only, not a commissioned independent fast cutoff, and neither is a USB-C source selector. Final selector/cutoff parts and wiring remain open until source labels, S99 cable/pinout/rating, and measured pulse envelope are known.

Do not select or energize a source selector or independent cutoff until the exact source models and S99 input cable wiring/rating are confirmed. Those parts must be chosen and commissioned for the measured path and proven to disconnect safely; generic relay or e-fuse ratings are not enough.

## 5. Agent-run test harness and telemetry

Implement a declarative, noninteractive test runner. A test manifest should identify the DUT/revision, installed cartridge/sample ID, supply, cable, firmware/build hash, manual tip setting, probe profile, repetitions, and approved hard limits. One command must execute a stage, sequence instruments and source switching, capture traces, evaluate pass/fail, and export a signed or checksummed result bundle. No live-stage prompts or manual button presses are permitted.

The host state machine should require: safety controller self-test; E-stop/interlock closed; all source outputs disabled; exactly one source selected; debug path isolated; tip/handle/MOSFET-area temperatures valid; installed tip/sample ID and no-contact state confirmed; instrument calibration current; firmware/build identity recorded; and source voltage/current settings within the manifest. The independent safety controller remains authoritative and fail-open. The human may install a tip only between runs after the previous run has shut down, disconnected the source, verified bus discharge, and confirmed cooldown. The runner exits at this boundary; it does not pause for a manual swap or accept an in-run prompt.

Capture synchronized timestamps for at least:

- firmware build, S99 revision/device identity, active profile, settings, boot/reset count, and test-run ID;
- raw tip-temperature/ADC samples, measurement timing, tip sensor validity, ambient temperature, handle temperature, and external MOSFET temperature;
- PWM command and actual gate waveform, pulse widths, frequency, current waveform, VBUS/DUT input voltage, and computed energy per pulse/run;
- PD/PPS contract, source current limit, renegotiations/detach, source-side current, charger status, and any BMS/bench-source faults;
- UART/debug continuity, relay/selector state, interlock/E-stop state, watchdog events, and shutdown cause;
- cold four-wire resistance for the installed cartridge, measured before the run and tied to its cartridge ID.

On any fault, the safety controller must latch the disconnect, the host must save the current trace and event timeline, and the run must stop. The script must not automatically retry, reconnect, or continue to another test after a fault. A human may inspect and reset the fixture after the hot area is safe; that reset is not part of an agent test run.

## 6. Supply and operating-condition matrix

## 7. Staged validation sequence

Each stage runs from a test manifest without operator input. The human remains physically present during all live-power stages and monitors the guarded hot area. Stop at the first failed gate; preserve logs and do not retry automatically.

### Stage 0 — design and source audit

Identify every supported S99 revision, schematic/BOM, sensor/sample timing, output topology, MOSFET/gate-driver limits, and debug/power isolation. Trace startup behavior from settings load through `preStartChecks()` and first nonzero PWM. Determine which signals are available while the heater is off and while it is on. Verify the hardware has no assumed current-sense path or auto-ID input unless the schematic and measurements prove otherwise.

Compare the local checkout with merged upstream PR #2248 and draft PR #2250. Establish the baseline on current upstream `dev` and make a separate integration test plan for both changes. Do not take their proposed current limits, frequencies, or controller gains as safety-qualified.

### Stage 1 — build, offline model, and recorded-trace replay

Build the S99 firmware and preserve its image/hash as the baseline. Develop an offline thermal/electrical model for candidate pulses using measured cartridge resistance curves, sensor timing, thermal response, input voltage, gate delay, and uncertainty bands. Replay existing traces where available; collect no-power sensor and ADC noise data.

Sweep the model over cold resistance, cartridge/sample spread, ambient temperature, starting tip temperature, ADC noise, sensor coupling, PWM timing, thermocouple sample windows, and plausible supply response. Find whether the 2.5 Ω and 5.5 Ω response distributions can be separated before the energy or pulse envelope reaches the approved limits. If safe distributions overlap or only separate after an unsafe pulse, stop and assess a hardware change or reject software-only detection.

### Stage 2 — harness, isolation, and fault injection with dummy loads

This is the first powered hardware stage, but still has no real tip installed. Do not start it until the exact three source models, the S99 input cable wiring/rating, and the commissioned independent cutoff are documented. Verify source switching, bus discharge, applicable USB-C contract changes, isolated UART continuity, logging, host watchdog, independent controller watchdog, E-stop, hard cutoff, and fail-open behavior. Use noninductive dummy loads and approved source settings to inject open/short load, overcurrent, overtemperature, telemetry loss, debug loss, host crash, controller reset, stale temperature, relay fault, source detach, USB-C renegotiation, and source cutoff.

Pass only if each fault drops power and latches the run before any software-only recovery can energize the DUT. Verify the telemetry bundle contains enough information to diagnose each injected fault. Confirm all tests run without prompts or human switching.

### Stage 3 — cold passive characterization

With power removed, verify the fixture measures ID/position and four-wire resistance for each of the six specified tips, plus continuity, ambient/tip/handle temperature, and no-contact position. Measure sensor noise without energizing the heater. Classify samples by measured resistance, not by bundled/JBC origin. Confirm the machine can reject a missing, open, shorted, unknown, warm, or mechanically contacted cartridge state. If the six samples do not include both 2.5 Ω and 5.5 Ω classes, obtain a separately identified example of the missing class before classifier probes.

### Stage 4 — output-stage characterization on dummy loads

Use a designated sacrificial S99 and noninductive loads representing the lowest-resistance case before fitting a real cartridge. If only the one planned S99 is available and its owner has not accepted it as the sacrificial measurement unit, this stage is blocked; obtain a separate sacrificial unit or resolve that risk first. Start at the lowest approved energy and use the independent cutoff. Capture gate-source, drain/source, VBUS, and current waveforms at each approved input point. Establish actual peak current, pulse shape, gate rise/fall, turn-off tail, switching loss, and temperature behavior. Include any no-chop or fixed-on state that can occur at a candidate supply point.

Use the continuity-mapped probe points and the baseline/capacitor sequence in §4. First characterize the unmodified board with no added capacitor. Keep input-current peaks, tip-current peaks, average currents, and energy-per-pulse as separate results. Step through only existing firmware-selected PWM rates while monitoring the MOSFET area; do not use timer arithmetic as a frequency limit. A capacitor comparison is a later, controlled A/B trial after the no-cap traces and component/source ratings have been reviewed.

Do not proceed to a live-tip probe until gate drive, pulse current, MOSFET operating point, and supply response stay inside the pre-approved limits with margin. Do not use low input voltage as a safety shortcut; qualify its gate-drive behavior independently. If safe limits cannot be established, stop and define the required board-level current limiter, gate-driver, current-sense, or cartridge-identification change.

### Stage 5 — bounded no-contact tip probes

Only after Stages 0–4 pass, test one measured tip at a time in a no-contact fixture. A human fits the selected tip with power off, the source disconnected, the bus discharged, and the iron cool; then a separate noninteractive run starts. Test measured 5.5 Ω samples first. Test 2.5 Ω only after the dummy-load evidence specifically covers its worst-case cold resistance and peak current. Tips with unknown or out-of-target resistance remain heater-off. Apply only an independently approved bounded probe schedule; its energy/timing/temperature limits are still to be measured, not guessed. Save raw thermal and electrical traces. Do not infer safety from low PWM duty alone. At the end, shut down and verify source disconnect, bus discharge, and cooldown before the runner exits for the next manual tip swap.

The classifier must return one of: known 2.5 Ω, known 5.5 Ω, or unknown/ambiguous. Unknown, stale, noisy, warm, externally heat-sunk, or out-of-range observations must fail closed: heater disabled and manual confirmation required. A low-confidence result must never be rounded to the 5.5 Ω profile. The test fixture must validate both correct classifications and every failure-to-detect path.

### Stage 6 — controlled source matrix

After a given tip's bounded probe passes on bench DC, the planned hardware runner should execute the selected source cases for that tip one at a time: the specified USB-C wall charger, the specified USB-C battery, then bench DC with the verified S99-compatible lead. The source selector should handle each switch automatically. Keep the probe schedule unchanged; do not let the classifier raise the power envelope. Change one factor at a time so source, cable, and tip effects remain identifiable. The USB-C battery case is blocked until its exact type, model, output ratings, and protection are confirmed. This initial source set does not qualify other chargers, power banks, battery packs, or contracts.

Trip, reset, unexpected contract change, VBUS sag beyond its approved limit, source cutoff, abnormal gate waveform, or MOSFET/handle/tip temperature excursion is a stop condition. Save the trace, latch off, and require a reviewed cause before another run.

### Stage 7 — blinded held-out qualification

Freeze the probe schedule and classifier threshold before qualification. Use cartridges and S99 units withheld from model fitting. The early screening target is at least 30 cold starts per tip class per represented condition with zero dangerous errors, where a 2.5 Ω cartridge classified as 5.5 Ω is dangerous. Misclassifying 5.5 Ω as 2.5 Ω is also a failure for product acceptance, though it is not the same overcurrent hazard. Qualification must include multiple samples, S99 revisions, and source classes.

Run a larger blinded release sample with an explicit statistical target. A pooled zero-failure sample of 300 gives only an approximate 1% upper 95% bound on the failure rate; it is not, by itself, evidence for a safety claim or permission to enable full power. If the project needs a tighter bound, size the sample accordingly. Separate class, revision, and source strata when reporting results; do not hide a weak subgroup in a pooled pass rate.

## 8. Pass/fail criteria and fail-safe behavior

The plan may move to firmware implementation only when all of these gates pass:

1. **Hardware envelope:** independently measured current, energy, voltage, gate, MOSFET, and temperature limits exist for the worst-case cold 2.5 Ω cartridge. Margin is documented against component ratings and supply behavior.
2. **Discriminability:** held-out 2.5 Ω and 5.5 Ω response distributions separate within the safe probe envelope across represented samples and conditions. A dangerous 2.5 Ω-to-5.5 Ω classification is zero in the pre-registered acceptance set.
3. **Fail closed:** missing tip, unknown tip, ambiguous score, sensor fault, stale sample, hot start, workpiece contact, source instability, invalid PD state, telemetry loss, or fixture/interlock fault leaves heater output off and requires explicit manual action or service reset.
4. **Independent cutoff:** fault injection proves the safety controller removes power if IronOS, the S99 MCU, the host, UART, or instrument control freezes or disconnects. The firmware never raises hardware cutoff limits.
5. **Source qualification:** each selected source model and tested USB-C contract passes without charger/battery trips, unexpected resets, unsafe voltage sag, thermal runaway, or gate-drive excursions. Report every model/contract combination separately.
6. **Reproducibility:** all traces, instrument calibration, firmware hashes, source profiles, cartridge resistance, and decisions are captured in machine-readable bundles. A second agent can replay the exact manifest and obtain the same classification and safety outcome without interactive input.
7. **Integration:** the feature passes against current upstream `dev`, the #2248 2.5 Ω output-stage work, and the #2250 PID draft (or their merged/rebased equivalents). PID changes must not invalidate the classifier response envelope. Re-run all affected stages after any output-stage, ADC timing, PD, or PID change.

Immediate abort-and-latch conditions include a hard current or energy limit; unexpected input voltage or source-current contract; PD detach/renegotiation or charger/BMS cutoff; MOSFET gate remaining partially enhanced; excessive turn-off tail; abnormal MOSFET, handle, or tip temperature/rate; thermal runaway; stale or missing telemetry; loss of any interlock; relay/source ambiguity; host or safety-controller watchdog event; or a classification confidence below the frozen threshold. Save traces and do not automatically retry.

Every live test stage requires a physically present human supervising heat risk and an accessible E-stop. Test scripts must be agent-executable from start to result without prompts or in-run human input. Tip changes are human actions only between completed runs after the runner has powered off, disconnected, verified discharge, and confirmed cooldown. Do not enable unattended hot testing unless the independent interlocks, hardware cutoff, fixture containment, and fault-injection suite have all been verified and explicitly reviewed.

## 9. CI, implementation gates, and release

The current CI in [`.github/workflows/push.yml`](../.github/workflows/push.yml) builds the model matrix and runs existing Python/BriefLZ checks; it has no S99 hardware-in-loop suite. Keep ordinary CI safe and reproducible without connected hardware:

- add deterministic host-side tests for classifier scoring, threshold boundaries, invalid/stale inputs, persistence/manual override behavior, and all fail-closed states;
- add model/replay tests using versioned input traces and assertions on classification, pulse schedule, energy, timeouts, and source-state transitions;
- retain the existing S99 and cross-model build matrix, checking flash/RAM impact and ensuring other Sequre models remain unchanged;
- create a separately gated hardware-runner job that accepts an explicit fixture/manifest, reports its calibration and interlock status, and uploads full traces. It must not silently run live power tests on a generic GitHub-hosted runner;
- make hardware results required before merge/release only after the rig is commissioned. Include a manual reviewer sign-off on the human-supervised safety evidence and a link to the machine-readable result bundle.

Begin firmware implementation only after the research/model gate, output-stage safety gate, and fixture gate are approved. Keep auto-detection disabled or opt-in until blinded qualification and #2248/#2250 integration pass. Preserve manual selection. Do not let detection alone select a higher power envelope; any subsequent power increase must remain within separately qualified supply and output-stage limits.

If no safe, discriminating probe exists on stock S99 hardware, stop software-only work. Produce a hardware-change proposal—such as a real current-sense path with fast independent cutoff, stronger/verified gate drive, or a direct cartridge-ID mechanism—or close the feature as infeasible for existing hardware.
